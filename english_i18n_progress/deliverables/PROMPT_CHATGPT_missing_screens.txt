أنت مطوّر Flutter و Laravel خبير. عندي منصة اسمها "منصة الوليد الهندسية": موقع Laravel وتطبيق Flutter.
التطبيق ناقصه شاشات موجودة بالموقع، وبدي تبنيها كشاشات Flutter أصلية (مش WebView)، بنفس محتوى ووظائف صفحة الموقع المقابلة.

الملفات اللي رح أرفقها لك:
- lib.zip: كود تطبيق Flutter كامل (191 ملف).
- resources.zip: واجهات الموقع (resources/views/*.blade.php)، وهي المرجع للشكل والمحتوى.
- app.zip و routes.zip: كود السيرفر (Controllers و Models و routes/api.php و routes/web.php).

====================================================================
قواعد إلزامية (اقرأها كاملة قبل ما تكتب أي كود)
====================================================================
1. قبل كل شاشة، افتح صفحة Blade المقابلة واقرأها كاملة، وافتح الـ Controller اللي بيعرضها من routes/web.php.
   الشاشة لازم تعرض نفس الحقول والأزرار والفلاتر والحالات (فاضي، تحميل، خطأ) والصلاحيات.
2. استعمل أسلوب التطبيق الموجود، ولا تخترع أسلوب جديد:
   - كل طلبات الشبكة من خلال الكلاس ApiService في lib/services/api_service.dart
     (دوال static، ترجع Future، والهيدرز من ApiService._headers(auth: true) اللي بتحط Bearer token و X-Office-Id).
     أضف الدوال الجديدة جوّا نفس الكلاس، وبنفس طريقة الدوال الموجودة (نفس معالجة الأخطاء ونفس شكل الإرجاع).
   - إدارة الحالة: provider (AuthProvider في lib/providers/auth_provider.dart لمعرفة المستخدم ودوره role).
   - رفع الملفات: AppFilePicker في lib/utils/app_file_picker.dart فقط (file_picker 12). ممنوع FilePicker.platform.
   - الألوان والثيم: lib/theme/app_theme.dart، والوضع الليلي لازم يشتغل.
   - اللغة: التطبيق عربي افتراضيًا (RTL) وفيه إنجليزي. أي نص بيظهر للمستخدم بتكتبه عربي وبتحط عليه .tr()
     مثل: Text('المستخدمين'.tr()) (من lib/i18n/i18n.dart). ولما تستعمل .tr() احذف const من الويدجت اللي فوقه.
     ممنوع تحط .tr() على قيم بتنقارن أو بتنبعت للسيرفر (مثل status == 'approved').
3. أضف كل شاشة جديدة للقائمة الجانبية lib/widgets/app_account_drawer.dart باستعمال _DrawerTile أو _SupportMenuTile
   (حسب القسم)، وبنفس شروط الصلاحيات (role / permissions) اللي بالموقع. ولا تمسح أي عنصر موجود.
4. إذا الـ API مش موجود بالسيرفر، اكتبه:
   - Route في routes/api.php داخل مجموعة auth:sanctum الموجودة، وبنفس البادئة وأسلوب التسمية.
   - Method في Controller (استعمل الـ Controller الموجود لنفس الميزة إذا في، أو أعمل Api Controller جديد).
   - أعد استعمال نفس منطق الـ Controller الخاص بالويب (نفس الـ Models والـ Policies والـ Validation والصلاحيات)،
     ورجّع JSON بنفس أسلوب باقي الـ API (مثلًا {"data": ...} أو {"message": ...} حسب الموجود).
   - لا تغيّر سلوك صفحات الويب الموجودة أبدًا.
5. سلّم كل ملف كاملًا (مش مقتطفات)، مع مساره الحقيقي بالمشروع، وحدد إذا الملف جديد أو معدّل.
   تأكد من الأقواس والـ imports، والكود لازم يمر flutter analyze بدون أخطاء.
6. اشتغل على دفعات: كل دفعة 3 إلى 5 شاشات، وبعد كل دفعة وقف واستنى ردّي "كمل".
   بآخر كل دفعة اكتب: الملفات الجديدة، الملفات المعدّلة، الـ Routes الجديدة، وأي أمر لازم أشغّله (مثل php artisan optimize:clear).
7. مستثنى تمامًا: أي إشي له علاقة بالكريبتو أو العملات الرقمية أو خزينة الكريبتو أو السحب الرقمي. لا تبنيه ولا تعدّله.
